# 设计与边界

## 计算模型独立于窗口

`CalculatorModel.press(key)` 接收一个已知按键，暴露显示文字、当前算式、错误和最近结果。Tkinter 不自行拼接或计算表达式，音效也不参与计算流程。按钮和键盘都调用同一个入口。

模型区分已提交的操作数／运算符、正在编辑的输入和计算结果，解决旧版“第二个操作数覆盖完整算式”的状态错误。先处理乘除、后处理加减，不使用 `eval` 或 `exec`。

## 数字与显示

计算采用 Decimal 局部上下文，精度为 28 位，不改变宿主程序的全局 Decimal 设置。输入长度、表达式长度和结果范围有上限，以免意外输入拖住界面。长结果的显示会缩短为科学计数法，后续计算使用内部值而非缩短后的显示文本。

百分号、正负号和平方根作用于当前操作数；这是明确的教学计算器规则，不模拟所有实体计算器的百分比或重复等号行为。README 的例子和测试共同说明这些边界。

## 音效不影响可用性

Pygame 是可选依赖，按需导入。加载失败、设备不可用、素材缺失或播放失败时，保留计算能力并显示静音状态。仅清理本实例使用的声音对象；如果混音器原本由外部代码初始化，不关闭外部的音频系统。

WAV 从脚本目录定位，音色由仓库内生成器合成。默认生成路径不依赖启动时的工作目录。

## 界面与数据

界面没有后台网络请求、账号或持久化数据库。历史保留最近 10 条成功结果，只驻留当前进程内。清除键清除当前算式，关闭窗口销毁本次会话。

首版目标是一个能独立运行、行为清楚的小型源码作品。没有打包器、更新服务、完整科学计算功能或高精度数学保证。
